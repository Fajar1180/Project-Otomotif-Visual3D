# LK-05 Rancangan Minimum Viable Product (MVP)

Bentuk MVP: satu fitur inti — diagnosis satu kategori kerusakan (mis. kerusakan mesin mobil), bukan seluruh platform.

| Komponen | Isi |
|----------|-----|
| Hipotesis | Pengguna mendapatkan diagnosa kerusakan mesin yang akurat dan cepat melalui cerita keluhan, sehingga mengurangi kunjungan tidak perlu ke bengkel |
| Manfaat / maksimal 3 fitur inti | 1) Input cerita keluhan (teks) + konteks kendaraan; 2) Hasil diagnosis dengan tingkat keparahan (DIY_EASY/DIY_HARD/WORKSHOP_REQUIRED); 3) Langkah perbaikan + rekomendasi suku cadang |
| Fitur yang ditunda | 3D Configurator, integrasi Shopee Affiliate, pencari bengkel via Maps, riwayat diagnosis, autentikasi pengguna |
| Proses manual / alat | FastAPI endpoint `POST /api/v1/diagnosis/analyze` (PRD §5), RAG pipeline dengan OpenAI/Claude, ground truth dari mekanik ahli untuk uji coba |
| Batas waktu dan biaya | 1 minggu untuk uji coba 10 kasus, biaya minimal (API LLM saja) |
| Risiko dan penanganan | Halusinasi AI → mitigasi RAG dengan grounding dan human-in-loop review (PRD §7) |

MVP tidak harus berupa aplikasi lengkap; mengikuti tujuan pembelajaran validasi asumsi teknis (LK-03).
